# 城市泳馆教练负荷分群

`hxwl-solo2611-6` · 聚类与画像解释

三座泳馆每周汇总教练课表、签到人次和代课单。市级排班室用上一完整周的实绩识别常见负荷与特殊排课，再决定下一轮补班由谁候补、谁维持原排、谁先复核或暂停增排。

## 模拟客户与工作流

澄湾市公共游泳服务中心 · 3 座泳馆、36 位教练

- 各馆在 Excel 里只按带课小时排序，晚高峰和代课压力容易被漏掉。
- 同样带课 26 小时，少量私教和高密度团课常被划到同一档。
- 临时跨馆代课靠群聊点名，异常签到与实际超负荷混在一张表上。

市级排班室复核分群及补班建议，三馆值班主管核对原课表、签到和代课单，再确认本轮补班候选名单。

## 业务模块

- 教练周负荷台账
- 密度分群试跑
- 群组诊断与补班建议
- 排班建议发布与回执
- 连续三周负荷迁移看板

## 计算口径

同一自然周每位教练一条，跨馆实绩由排班室先合并到归属馆。高峰采用三馆统一口径：工作日 17:00–21:00、周末 09:00–17:00。带课时长、高峰带课、学员签到人次和临时代课班次分别减当周均值、除以总体标准差，常量列的标准分记为 0。DBSCAN 用标准化欧氏距离找密度相连的核心点，并标出边界和噪声。边界点靠近多个群时取最近核心点，等距时取较小群号。群号随当批数据和参数变化。候补需由馆方核对资质、实际可用时段及下一周课表。

样例输入为 `澄湾三馆教练周负荷_2026-11-16.csv`，见 `backend/demo/sample.csv`。相同输入与参数复现相同结果。格式错误在导入时提示，样本量或业务约束不满足时在后台运行结果中提示。

负荷迁移看板跟踪连续三周：每段以前一周全市均值与总体标准差为尺度标准化后一周实绩，按前一周核心群判断去向（ε 邻域内取最近核心教练的群，等距取较小群号，够不到核心教练记为噪声）。转馆按同一教练编号比较前后两周归属泳馆，新进与缺席教练单列。周数据更正按各周修订号取最新，乱序到达的旧修订只存档不触发重算；按较早修订算出的结果晚出来也不顶掉新版。中间周更正后两段一起重算，算齐再一次性切换，任一段失败时看板继续显示整套旧版。已发出的补班建议保留发出时的迁移依据，可随时回查。

## 一班如何使用

1. 2026-11-24 08:20，排班室导出 11 月 16 日至 22 日的澄湾三馆教练周负荷_2026-11-16.csv。
2. 08:35，在教练周负荷台账导入 36 条教练记录，按归属馆核对教练编号和全市统一的高峰口径。
3. 09:00，在密度分群试跑输入 ε 0.65、最少邻居 5、暂停增排线 28 小时、拟补班 6 小时。
4. 09:15，打开群组诊断，查看各组带课时长中位数和逐位教练的邻居数，核对核心、边界和噪声。
5. 09:35，请值班主管核对 CW-034 的 7 小时带课、180 人次签到及 8 个代课班次，确认是否存在跨馆重复汇总。
6. 10:05，比对 CW-001 的 10 小时带课余量与 CW-035 的 43 小时实绩，按建议分别进入候补核对和暂停增排流程。
7. 10:30，发布排班建议给澄湾市泳馆排班室和三馆值班主管组，并收集实际可用时段及复核回执。

## 启动与本地开发

```sh
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

停止本地服务可执行 `docker compose down`。仅清理演示数据时使用 `docker compose down -v --remove-orphans`。

浏览器 `http://127.0.0.1:18315`，API `http://127.0.0.1:19315`，数据库宿主端口 `17815`。

前端由 Nginx 提供原生 HTML/CSS/JS，并将 `/api/` 转发给 FastAPI。Python 3.11 Worker 使用 Redis 唤醒和 MySQL 8.0 运行租约，生成的 CSV 由命名卷共享。可编辑 `frontend/src/pages`、`backend/src/services/analysis.py` 和 `backend/demo` 后执行 `docker compose up -d --build --wait`。Compose 默认映射到本机回环地址。更改 `.env` 可配置端口、数据库密码、JWT 密钥以及 `SEED_DEMO` 种子开关。演示凭据适用于本机模拟数据。

| 角色 | 账号 | 密码 | 工作内容 |
|---|---|---|---|
| 主管 | admin | admin-demo-2611 | 查看审计，复核运行，安排与停用分发计划 |
| 分析员 | analyst | analyst-demo-2611 | 导入 CSV、运行计算、下载结果 |
| 只读 | viewer | viewer-demo-2611 | 查看数据、结果和投递回执，下载 CSV |

角色、运行状态和复核状态在 `backend/src/constants/enums.py` 与 `frontend/src/constants/enums.js` 同步定义。角色参与登录、路由授权和工具栏控制。运行状态在 Worker、任务接口和结果页使用。复核状态在运行模型、复核接口和交付页使用。

核心实体为 CSV 数据批次、分析运行、分发计划及其投递回执。业务参数与真实模拟数据位于 `backend/demo/`。后端分为 routes、controllers、services、models、schemas 和中间件，前端分为 api、store、组件和业务页面。授权模式见 [LICENSE](LICENSE)。
